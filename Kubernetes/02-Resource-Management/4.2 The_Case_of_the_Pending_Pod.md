# 4.2 : Memory Limit Exceeded → **OOMKilled**

https://drive.google.com/file/d/1l0bQJNRRjrxzuIn0dwAb4AMbM67MIgrp/view?usp=sharing

### 🔍 YAML Breakdown

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nnappone
  namespace: learning
  labels:
    app: nnappone
spec:
  containers:
    - name: crackone-app
      image: lovelearnlinux/stress:latest     # ← Special image with `stress` tool
      resources:
        requests:
          memory: "150Mi"   # Scheduler reserves 150Mi
        limits:
          memory: "250Mi"   # Hard ceiling = 250Mi
      command: ["stress"]
      args: ["--vm", "1", "--vm-bytes", "275M", "--vm-hang", "1"]

```

> 💥 What the stress command does:
> 
> - `-vm 1` → Start 1 worker
> - `-vm-bytes 275M` → **Allocate 275 MB of memory**
> - `-vm-hang 1` → Lock the memory (don’t release it)

> ⚠️ Conflict:
> 
> 
> Pod tries to use **275 MB** > **limit = 250 MiB** → **Killed by OOM Killer!**
> 

> 🔍 Note: 275M (Megabytes = 1000²) ≈ 262 MiB (Mebibytes = 1024²) → still > 250 MiB
> 

---

### 📌 What Happens at Runtime?

| Phase | What Occurs |
| --- | --- |
| **1. Scheduling** | ✅ Success! Node has ≥150Mi free → Pod starts |
| **2. Container Runs** | `stress` allocates memory → reaches ~262 MiB |
| **3. Memory > 250MiB** | **Container Runtime (containerd/docker) triggers OOM Killer** |
| **4. Pod Status** | Changes to **`OOMKilled`** → restarts (if `restartPolicy: Always`) |
| **5. Event Logged** | `Exit Code 137` = **128 + 9** → signal **SIGKILL** |

> 💡 Key Difference from CPU:
> 
> - **CPU overuse** → **throttled** (slowed, but survives)
> - **Memory overuse** → **killed immediately** (no second chances!)

### 🔧 Steps

```bash
# 1. Create namespace

# 🔍 Critical lines in "Events":
#   Last State:     Terminated
#     Reason:       OOMKilled
#     Exit Code:    137
#     ...
#   Restart Count:  2+

# 5. Check logs (may be empty if killed instantly)
kubectl logs nnappone -n learning --previous

# 6. Clean up
kubectl delete pod nnappone -n learning
kubectl delete namespace learning

```

### 🔍 Understanding Exit Code 137

| Signal | Meaning |
| --- | --- |
| **SIGKILL (9)** | Force-kill process (can’t be caught/ignored) |
| **Exit Code = 128 + 9 = 137** | Standard way to indicate **killed by SIGKILL** |

> ✅ In Kubernetes:
> 
> 
> **Exit Code 137 + Reason: OOMKilled** = **memory limit exceeded**
>

### 🛠️ How to Fix It?

### ✅ Option 1: Increase Memory Limit

```yaml
resources:
  limits:
    memory: "300Mi"   # > 275M (~262Mi)

```

### ✅ Option 2: Reduce Memory Usage

```yaml
args: ["--vm-bytes", "200M"]  # Stay under 250Mi

```

### ✅ Option 3: Add Memory Monitoring

Use **Prometheus + Grafana** to track:

- `container_memory_usage_bytes`
- `container_memory_working_set_bytes`

> 📊 Rule of Thumb:
> 
> 
> Set `limits` ≈ **peak usage + 20% buffer**
> 
> Set `requests` ≈ **average usage**
>

### ❓ Common Questions

**Q: Why not just set huge memory limits?**

A: Wastes cluster capacity → fewer Pods per node → higher costs.

**Q: Can I catch OOM in app logs?**

A: ❌ No — the process is **force-killed** by the kernel. Use **metrics** instead.

**Q: Does `restartPolicy: Never` prevent restarts?**

A: Yes — but the Pod stays in **`CrashLoopBackOff`** if it fails on first run.

**Q: What’s the difference between `Mi` and `M`?**

A:

- `250Mi` = 250 × 1024² = **262,144,000 bytes**
- `275M` = 275 × 1000² = **275,000,000 bytes** → **still exceeds 250Mi!**

### 📊 Best Practices for Memory Management

| Practice | Why |
| --- | --- |
| **Always set `requests` and `limits`** | Avoid BestEffort, control scheduling |
| **Monitor real usage** | Don’t guess — use `kubectl top pods` |
| **Test memory limits** | Use `stress` image in staging |
| **Use liveness/readiness probes** | Detect memory leaks early |

```bash
# See real memory usage
kubectl top pods -n learning

```

### ➡️ Summary

✅ **Memory overuse → OOMKilled** (immediate kill, exit code 137).

🔍 Diagnose with: `kubectl describe pod` → **"Reason: OOMKilled"**.

📊 Memory enforcement is **hard limit** (unlike CPU throttling).

🛠️ Fix by: **increasing limit** or **reducing usage**.

🧪 Use `stress` image to **test limits safely**.
