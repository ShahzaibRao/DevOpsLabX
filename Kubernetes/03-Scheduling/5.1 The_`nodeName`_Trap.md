# 5.1 : Scheduling to a Specific Node (`nodeName`)

https://drive.google.com/file/d/1rt8QiHNs37SyGVv0Jddhjb-QY9P6gH6u/view?usp=sharing

### 🔍 YAML Breakdown

```yaml
apiVersion: v1
kind: Pod
metadata: 
  name: nnappone
  namespace: learning
  labels:
    app: nnappone
spec:
  nodeName: nodeone.example.com   # ← HARD assignment to this node
  containers:
    - name: crackone-app
      image: nginx
      resources:
        requests:
          memory: "300Mi"
        limits:
          memory: "500Mi"

```

> 🔑 Key Field: spec.nodeName: nodeone.example.com
> 
> 
> → **Bypasses the Kubernetes scheduler entirely!**
> 
> → Pod is **forced** onto this node — no checks for resources, taints, or capacity.
> 

---

### 📌 How `nodeName` Works

| Behavior | Explanation |
| --- | --- |
| **Scheduler Bypassed** | Normally, scheduler picks best node. Here, **you decide**. |
| **No Validation** | Kubernetes **won’t check** if node exists, has resources, or is ready. |
| **If node is down/unavailable** | Pod stays in **`Pending` forever** (no retry on other nodes). |
| **Use Case** | Rare! Only for **debugging**, **single-node clusters**, or **very special workloads**. |

> ⚠️ Why Avoid in Production?
> 
> - Breaks **high availability**
> - Prevents **auto-scaling** and **rescheduling**
> - Fragile (node name changes = Pod breaks)

> ✅ Better Alternatives:
> 
> - `nodeSelector` (simple label-based)
> - `nodeAffinity` (flexible, expressive)
> - `podAntiAffinity` (for spreading workloads)

---

### 🧪 Lab: Deploy Pod to Specific Node

> 💡 Note: You likely don’t have a node named nodeone.example.com — so this Pod will fail to schedule. That’s expected! We’ll fix it.
> 

### 🔧 Step 1: See What Nodes You Have

```bash
kubectl get nodes
# Example output:
# NAME           STATUS   ROLES           AGE   VERSION
# minikube       Ready    control-plane   10m   v1.28.0
# minikube-m02   Ready    <none>          10m   v1.28.0

```

> 📝 Pick an actual node name (e.g., minikube).
> 

### 🔧 Step 2: Edit YAML to Use Real Node Name

```yaml
# pod-for-specific-node.yml (updated)
spec:
  nodeName: minikube   # ← Replace with YOUR node name
  containers:
    - name: crackone-app
      image: nginx
      resources:
        requests:
          memory: "300Mi"
        limits:
          memory: "500Mi"

```

### 🔧 Step 3: Run the Lab

```bash
# 1. Create namespace
kubectl create namespace learning

# 2. Apply Pod
kubectl apply -f pod-for-specific-node.yml

# 3. Check status
kubectl get pods -n learning -o wide

# ✅ Expected:
# NAME       READY   STATUS    NODE       ...
# nnappone   1/1     Running   minikube   ...

# 4. Verify it’s on the right node
kubectl describe pod nnappone -n learning | grep "Node:"

# 5. Clean up
kubectl delete pod nnappone -n learning
kubectl delete namespace learning

```

---

### ❓ What If Node Doesn’t Exist?

If you keep `nodeName: nodeone.example.com` (fake name):

```bash
kubectl get pods -n learning
# NAME       READY   STATUS    RESTARTS   AGE
# nnappone   0/1     Pending   0          30s

kubectl describe pod nnappone -n learning
# Events:
#   Warning  FailedScheduling  5s  default-scheduler  0/2 nodes are available: 2 node(s) had taint {node.kubernetes.io/not-ready: }, that the pod didn't tolerate.
#   OR (if node unknown):
#   Warning  FailedScheduling  ...  node(s) had no available volume zone, node(s) were unschedulable

```

> 🔍 Key Insight:
> 
> 
> Even with `nodeName`, if the node is **not ready** or **doesn’t exist**, Pod stays **Pending**.
> 

---

### 🆚 Comparison: Scheduling Methods

| Method | Flexibility | Scheduler Used? | Production-Ready? |
| --- | --- | --- | --- |
| `nodeName` | ❌ None | ❌ No | ❌ Rarely |
| `nodeSelector` | ✅ Medium | ✅ Yes | ✅ Yes |
| `nodeAffinity` | ✅✅ High | ✅ Yes | ✅✅ Yes |
| `podAntiAffinity` | ✅✅ High | ✅ Yes | ✅✅ Critical for HA |

> 🎯 Rule of Thumb:
> 
> 
> **Never use `nodeName` in production** unless you have a **very strong reason** (e.g., hardware-bound workload).
> 

---

### ➡️ Summary

✅ `nodeName` **forces** a Pod onto a specific node.

⚠️ **Bypasses scheduler** → no resource/taint checks.

🔍 Use only for **debugging** or **learning**.

🛠️ In lab: **replace fake node name** with real one (`kubectl get nodes`).
