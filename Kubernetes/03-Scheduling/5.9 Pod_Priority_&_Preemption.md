### 🔍 Part 1: PriorityClass Definition

```yaml
# mission-critical-priority-class.yaml
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
meta
  name: mission-critical-apps
value: 1000000                 # ← Higher = more important
preemptionPolicy: Never        # ← Key setting!
globalDefault: false
description: "For mission-critical apps"

```

> 🔑 Key Fields:
> 
> - **`value`**: Priority score (1 to 1,000,000,000). **Higher = scheduled first**.
> - **`preemptionPolicy`**:
>     - `PreemptLowerPriority` (default): **Evict lower-priority Pods** to make room
>     - `Never`: **Don’t evict** — just wait in queue (your example)
> - **`globalDefault: false`**: Don’t apply to Pods without `priorityClassName`

> 💡 Default Critical Classes (built into Kubernetes):
> 
> - `system-cluster-critical` → `value: 2000000000` (CoreDNS, CNI, Metrics Server)
> - `system-node-critical` → `value: 2000001000` (etcd, kubelet, API server)

### 🔍 Part 2: Pod Using PriorityClass

```yaml
# mission-critical-pod.yaml
apiVersion: v1
kind: Pod
meta
  name: topgun
  labels:
    app: topgun
    env: prod
spec:
  containers:
  - name: boxone
    image: nginx
    imagePullPolicy: IfNotPresent
  priorityClassName: mission-critical-apps  # ← Links to PriorityClass

```

> ✅ This Pod will:
> 
> - Be placed **ahead of lower-priority Pods** in scheduling queue
> - **NOT preempt** others (because `preemptionPolicy: Never`)
> - Wait **indefinitely** if no resources are available

### 📌 How Priority & Preemption Work

| Scenario | Behavior |
| --- | --- |
| **Resources available** | High-priority Pod schedules **immediately** |
| **No resources, `preemptionPolicy: PreemptLowerPriority`** | Scheduler **evicts lowest-priority Pods** to free space |
| **No resources, `preemptionPolicy: Never`** | Pod **waits in queue** — no eviction |
| **All Pods have same priority** | First-come, first-served |

> ⚠️ Preemption is a last resort — scheduler tries to find space without eviction first.
>

### 🧪 k3s Lab: Priority & Preemption in Action

> ✅ Assumption: Your k3s cluster has limited CPU/memory (or we’ll simulate scarcity).
> 

### 🔧 Step 1: Create PriorityClass

```bash
# Save as mission-critical-priority-class.yaml
cat <<EOF | kubectl apply -f -
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
meta
  name: mission-critical-apps
value: 1000000
preemptionPolicy: PreemptLowerPriority  # ← Changed to test preemption!
globalDefault: false
description: "For mission-critical apps"
EOF

```

> 💡 We set preemptionPolicy: PreemptLowerPriority to see eviction in action.
>

### 🔧 Step 4: Observe Preemption

```bash
# Watch Pods
kubectl get pods -w

# ✅ Expected:
# - One of `filler-1` or `filler-2` gets **terminated**
# - `topgun` becomes **Running**

# Check events
kubectl describe pod topgun
# Events: Successfully assigned...

# Check evicted Pod
kubectl get pods
# filler-1   0/1   Terminated   0     2m

```

> 🔍 Why only one filler evicted?
> 
> 
> Scheduler calculates: *"Evicting one filler frees enough resources for `topgun`."*
>

### 💡 Real-World Use Cases

| Priority Level | Use Case |
| --- | --- |
| **`system-node-critical`** | etcd, kube-apiserver |
| **`system-cluster-critical`** | CoreDNS, CNI, Metrics Server |
| **Custom High (1,000,000+)** | Payment processing, real-time trading |
| **Medium (10,000)** | User-facing web apps |
| **Low (100)** | Batch jobs, log processors |

> ✅ Best Practice:
> 
> - Use `preemptionPolicy: Never` for **critical apps** (don’t cause collateral damage)
> - Use `PreemptLowerPriority` for **urgent but non-critical** workloads

### ❓ Common Questions

**Q: Are PriorityClasses namespaced?**

A: ❌ **No!** They’re **cluster-scoped** — available to all namespaces.

**Q: What if two Pods have same priority?**

A: Scheduled in **creation timestamp order** (FIFO).

**Q: Can I change a Pod’s priority after creation?**

A: ❌ **No!** Priority is set at creation and **immutable**.

**Q: Does preemption respect PodDisruptionBudgets (PDB)?**

A: ✅ **Yes!** Scheduler **won’t preempt** if it violates a PDB.

**Q: Is priority enabled by default in k3s?**

A: ✅ **Yes!** k3s enables the **`PodPriority`** feature gate by default.
