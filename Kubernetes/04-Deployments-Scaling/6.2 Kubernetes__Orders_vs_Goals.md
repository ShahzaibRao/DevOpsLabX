### 🔍 Script Breakdown (`imperative-deployment.sh`)

```bash
#!/bin/sh
# A: Create Deployment with latest nginx
kubectl create deployment nginx-imperative --image=nginx:latest

# B: Scale to 3 replicas
kubectl scale deployment/nginx-imperative --replicas=3

# C & D: Add metadata annotations
kubectl annotate deployment/nginx-imperative environment=prod
kubectl annotate deployment/nginx-imperative organization=sales

```

> 🔑 Key Insight:
> 
> 
> This script uses **imperative commands** — you tell Kubernetes **what to do step-by-step**.
> 

---

### 📌 Imperative vs Declarative: Core Differences

| Aspect | **Imperative** (`kubectl create ...`) | **Declarative** (`kubectl apply -f ...`) |
| --- | --- | --- |
| **Approach** | "Do this, then that" | "Here’s the desired state — make it so" |
| **Audit Trail** | ❌ Hard to track changes | ✅ Full history in Git |
| **Reproducibility** | ❌ Manual steps | ✅ `git clone && kubectl apply` |
| **Team Collaboration** | ❌ Error-prone | ✅ Code-reviewed YAML |
| **Rollback** | ❌ Manual | ✅ `git revert && kubectl apply` |
| **Use Case** | Quick testing, learning | **Production, GitOps, CI/CD** |

> ✅ Kubernetes Best Practice:
> 
> 
> **Use declarative YAML for production**
> 
> Use imperative for **quick experiments**
>

### 🔧 Step 2: Export to YAML (See What Was Created)

```bash
# Get the full Deployment spec
kubectl get deployment nginx-imperative -o yaml > nginx-imperative.yaml

# View key parts
grep -A 5 "replicas\\|image\\|annotations" nginx-imperative.yaml

```

> 🔍 You’ll see:
> 
> 
> ```yaml
> replicas: 3
> template:
>   spec:
>     containers:
>     - image: nginx:latest
> annotations:
>   environment: prod
>   organization: sales
> 
> ```
> 

### 🔧 Step 3: Try to "Recreate" Declaratively

> 💡 Now you have a YAML file — you could version-control it!
> 

```bash
# Delete imperative Deployment
kubectl delete deployment nginx-imperative

# Recreate from YAML
kubectl apply -f nginx-imperative.yaml

# Result: Identical Deployment!

```

> ✅ This is the power of declarative:
> 
> 
> Once you have YAML, you’re in **GitOps territory**.
>

### ⚠️ Critical Warning: `:latest` Tag

Your script uses:

```bash
--image=nginx:latest

```

> 🚨 Never use :latest in production!
> 
> - **Non-deterministic**: `latest` changes over time
> - **Breaks rollbacks**: You can’t go back to "previous latest"
> - **Security risk**: Unknown image version

> ✅ Fix: Always use specific tags:
> 
> 
> ```bash
> kubectl create deployment nginx --image=nginx:1.25
> 
> ```
>

### 💡 When to Use Imperative Commands

| Scenario | Command |
| --- | --- |
| **Quick test** | `kubectl create deployment test --image=busybox` |
| **Debugging** | `kubectl scale deployment/app --replicas=0` |
| **One-off tasks** | `kubectl annotate pod/p1 owner=john` |
| **Learning** | Great for exploring CLI |

> 🎯 Rule of Thumb:
> 
> 
> If you’ll **do it more than once**, **write YAML**.
>

### ❓ Common Questions

**Q: Can I mix imperative and declarative?**

A: ⚠️ **Dangerous!** If you `kubectl apply -f` then `kubectl scale`, the next `apply` will **overwrite the scale** (unless you use `--server-side` or `kubectl scale` consistently).

**Q: How do I see the effective state?**

A: Use `kubectl get -o yaml` — it shows the **live state**, regardless of how it was created.

**Q: What’s the `--dry-run=client` trick?**

A: Generate YAML without applying:

```bash
kubectl create deployment nginx --image=nginx:1.25 --dry-run=client -o yaml > deployment.yaml

```

**Q: Are annotations stored in etcd?**

A: ✅ Yes! They’re part of the object metadata — visible in `kubectl get -o yaml`.

### ➡️ Summary

✅ **Imperative** = CLI commands (`kubectl create`, `scale`, `annotate`)

✅ **Declarative** = YAML files (`kubectl apply -f`)

⚠️ **Avoid `:latest`** — use specific image tags

🔍 **Export imperative workloads to YAML** for reproducibility

🛠️ **Use imperative for learning/testing, declarative for production**
