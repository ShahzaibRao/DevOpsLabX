### 🔍 Current YAML Breakdown

```yaml
apiVersion: apps/v1
kind: Deployment
meta
  name: nginx-declarative
  annotations:
    environment: prod
    organization: sales
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx          # ← Good: uses standard 'app' label
  template:
    meta
      labels:
        app: nginx         # ← Must match selector
    spec:
      containers:
      - name: nginx
        image: nginx:latest  # ⚠️ Problem!

```

> ✅ What’s Good:
> 
> - Uses **standard `app` label** (better than `run`)
> - Includes **annotations** for metadata
> - Clean, version-controllable YAML

> ⚠️ What’s Missing (vs deployment-one.yml):
> 
> 1. **`:latest` tag** → non-deterministic
> 2. **No resource requests/limits** → can’t use HPA, poor scheduling
> 3. **No liveness/readiness probes** → no health checks
> 4. **No update strategy** → uses default (`maxSurge: 25%`, `maxUnavailable: 25%`)
> 5. **No ports declaration** → optional but good practice

### 🛠️ Enhanced Production-Ready Version

Here’s how to **upgrade** this for production:

```yaml
# declarative-deployment.yaml (ENHANCED)
apiVersion: apps/v1
kind: Deployment
meta
  name: nginx-declarative
  annotations:
    environment: prod
    organization: sales
    kubernetes.io/change-cause: "nginx 1.25 with health checks"
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1          # +1 extra during update
      maxUnavailable: 0    # zero downtime
  selector:
    matchLabels:
      app: nginx
  template:
    meta
      labels:
        app: nginx
        version: v1.25     # ← Optional: track version in labels
    spec:
      containers:
      - name: nginx
        image: nginx:1.25-alpine  # ✅ Specific, lightweight tag
        ports:
        - containerPort: 80
          name: http
        resources:
          requests:
            cpu: "100m"
            memory: "128Mi"
          limits:
            cpu: "200m"
            memory: "256Mi"
        livenessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 10
          periodSeconds: 20
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 10

```

> ✅ Key Improvements:
> 
> - **Specific image tag** (`1.25-alpine`)
> - **Resource requests/limits**
> - **Liveness + Readiness probes**
> - **Zero-downtime strategy**
> - **Standardized labels**

### 🆚 Imperative vs Declarative: Final Comparison

| Task | Imperative | Declarative |
| --- | --- | --- |
| **Create** | `kubectl create deployment ...` | `kubectl apply -f deployment.yaml` |
| **Scale** | `kubectl scale --replicas=3` | Edit `replicas: 3` in YAML → `apply` |
| **Update Image** | `kubectl set image deployment/nginx nginx=nginx:1.25` | Edit YAML → `apply` |
| **Add Probes** | ❌ Very hard | ✅ Edit YAML → `apply` |
| **GitOps** | ❌ Impossible | ✅ Native support |

> 🎯 Best Practice:
> 
> 
> Use **imperative for learning**, **declarative for everything else**.
>

### 💡 Pro Tips for k3s

1. **Always specify resource requests** → k3s clusters are often resource-constrained.
2. **Use `alpine` images** → smaller, faster, more secure.
3. **Add `readinessProbe`** → prevents sending traffic to unready Pods (critical for Services).
4. **Version your Deployments** → use Git tags or ArgoCD.

### ❓ Common Questions

**Q: Can I use `kubectl apply` with imperative-created objects?**

A: ✅ Yes! But **don’t mix** — once you `apply`, stick to YAML.

**Q: What if I forget `selector.matchLabels`?**

A: Kubernetes **auto-generates** it from `template.labels` — but **explicit is better**.

**Q: Are annotations required?**

A: ❌ No — but they’re great for **team metadata** (owner, env, cost center).

**Q: Why `app: nginx` and not `app.kubernetes.io/name: nginx`?**

A: Both work! But [Kubernetes recommends](https://kubernetes.io/docs/concepts/overview/working-with-objects/common-labels/) the latter for production:

```yaml
labels:
  app.kubernetes.io/name: nginx
  app.kubernetes.io/instance: nginx-prod
  app.kubernetes.io/version: "1.25"

```
