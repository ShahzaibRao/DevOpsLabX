### 🔧 Corrected & Modernized YAML

```yaml
apiVersion: apps/v1                  # ✅ Modern API (extensions/v1beta1 is DEPRECATED)
kind: Deployment
metadata:
  name: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx                    # ✅ Required in apps/v1
  template:
    metadata:
      labels:
        app: nginx
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
          - topologyKey: kubernetes.io/hostname
            labelSelector:
              matchLabels:
                app: nginx          # ← Avoid nodes running Pods with this label
      containers:                    # ✅ Plural "containers" (was "container")
        - name: nginx
          image: nginx:1.25-alpine   # ✅ Avoid :latest
          ports:
            - containerPort: 80

```

> 🔑 Key Fixes:
> 
> - **`apiVersion: apps/v1`** → current standard (since Kubernetes 1.9)
> - **Added `selector.matchLabels`** → required in `apps/v1`
> - **`containers` (plural)** → correct field name
> - **Specific image tag** → avoid `:latest`

### 📌 How Anti-Affinity Works in Deployments

| Field | Purpose |
| --- | --- |
| **`podAntiAffinity`** | "Don’t schedule on nodes that match this rule" |
| **`labelSelector.matchLabels`** | Target **your own Pods** (`app: nginx`) |
| **`topologyKey: kubernetes.io/hostname`** | Scope = **same node** |
| **`requiredDuringScheduling...`** | Hard rule — **must** spread Pods |

> 🎯 Your Rule:
> 
> 
> *"Do **NOT** schedule two `nginx` Pods on the same node."*
> 

> 💡 Why This Matters:
> 
> - If a node fails, **only 1 replica is lost** (not all 3!)
> - Critical for **high availability** in production

### 🧪 k3s Lab: Verify Anti-Affinity Spread

> ✅ Assumption: You have ≥3 worker nodes in your k3s cluster.
> 
> 
> (If you have only 2 nodes, reduce `replicas: 2`)
> 

### 🔧 Step 1: Deploy the Fixed YAML

```bash
# Save as deployment-with-anti-affinity-fixed.yaml
kubectl apply -f deployment-with-anti-affinity-fixed.yaml

# Wait for Pods to be ready
kubectl get pods -l app=nginx -o wide

```

### 🔧 Step 2: Verify Pod Distribution

```bash
# Check node distribution
kubectl get pods -l app=nginx -o wide

# ✅ Expected (on 3-node cluster):
# NAME                     READY   NODE
# nginx-7df8b9b5d4-abc12   1/1     k3s-node1
# nginx-7df8b9b5d4-def34   1/1     k3s-node2
# nginx-7df8b9b5d4-ghi56   1/1     k3s-node3

# ❌ If you see 2 Pods on same node → anti-affinity failed!

```

### 🔧 Step 3: Test Failure (Not Enough Nodes)

> 💡 If you have only 2 nodes but replicas: 3:
> 

```bash
# One Pod will stay Pending!
kubectl get pods -l app=nginx

# Describe to confirm
kubectl describe pod <pending-pod>
# Events: 0/2 nodes available: 2 node(s) didn't match pod anti-affinity rules.

```

> 🔍 Solution:
> 
> - Add more nodes, OR
> - Use **`preferredDuringScheduling...`** for soft anti-affinity

### 🔧 Step 4: Clean Up

```bash
kubectl delete deployment nginx

```

### 💡 Pro Tips for k3s

1. **Always use `required` anti-affinity for critical apps**
2. **For zone-level HA** (if multi-AZ):
    
    ```yaml
    topologyKey: topology.kubernetes.io/zone
    
    ```
    
3. **Combine with node anti-affinity** for multi-layer isolation
4. **Verify with `kubectl get pods -o wide`** after every deploy

### 🆚 Required vs Preferred Anti-Affinity

| Type | Behavior | Use Case |
| --- | --- | --- |
| **`requiredDuringScheduling...`** | Hard rule — **blocks scheduling** if violated | Critical apps (databases, payment) |
| **`preferredDuringScheduling...`** | Soft rule — **tries to spread**, but won’t block | Best-effort HA (logging, monitoring) |

> ✅ Your YAML uses required → correct for production.
>

### ❓ Common Questions

**Q: What if I have more replicas than nodes?**

A: ❌ **Pods will stay Pending** (with `required` anti-affinity).

✅ **Fix**: Use `preferred` or add nodes.

**Q: Does anti-affinity work with DaemonSets?**

A: ❌ **No need!** DaemonSets **already run 1 Pod per node**.

**Q: Can I use anti-affinity across namespaces?**

A: ✅ Yes! Add `namespaces: ["other-ns"]` to `labelSelector`.

**Q: Why `kubernetes.io/hostname` and not node name?**

A: `kubernetes.io/hostname` is a **standard label** automatically applied to all nodes.
