### 🔍 YAML Breakdown

```yaml
# Service
apiVersion: v1
kind: Service
metadata:
  name: nnweb-svc
  namespace: learning
  labels:
    app: hello-nn
spec:
  type: NodePort          # ← Exposes on ALL node IPs
  ports:
  - port: 80              # ← Service port (internal)
    nodePort: 30003       # ← Fixed external port (30000-32767)
    protocol: TCP
  selector:
    app: hello-nn         # ← Must match Deployment labels

---
# Deployment
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-deploy
  namespace: learning
spec:
  replicas: 2
  selector:
    matchLabels:
      app: hello-nn
  template:
    metadata:
      labels:
        app: hello-nn
    spec:
      containers:
      - name: webserver-pod
        image: lovelearnlinux/webserver:v1
        ports:
        - containerPort: 80

```

> 🔑 Key Insight:
> 
> - **NodePort Service** opens port `30003` on **every node** in the cluster
> - Traffic to `http://<ANY-NODE-IP>:30003` → load-balanced to **Pods with `app: hello-nn`**

---

### 📌 How NodePort Works in k3s

| Component | Role |
| --- | --- |
| **`type: NodePort`** | Tells Kubernetes to open a port on all nodes |
| **`nodePort: 30003`** | Fixed external port (optional; if omitted, k3s assigns random 30000-32767) |
| **`port: 80`** | Internal Service port (used by ClusterIP) |
| **`selector`** | Links to Pods (`app: hello-nn`) |
| **kube-proxy** | Configures **iptables rules** on each node to forward `:30003` → Pods |

> 🎯 Access Methods:
> 
> 1. **Internal**: `curl http://nnweb-svc.learning.svc:80` (from inside cluster)
> 2. **External**: `curl http://<NODE-IP>:30003` (from laptop, browser, etc.)

> 💡 k3s Advantage:
> 
> 
> No cloud provider needed — **NodePort works out-of-the-box** on bare metal!
>

### 💡 Real-World NodePort Best Practices

| Practice | Why |
| --- | --- |
| **Use fixed `nodePort`** (e.g., `30003`) | Easier firewall rules, documentation |
| **Restrict with firewall** | Only allow trusted IPs to `:30003` |
| **Prefer Ingress for HTTP/S** | Better routing, TLS termination, path-based rules |
| **Avoid for production public apps** | Use **LoadBalancer** (MetalLB) or **Ingress** instead |

> ✅ When to use NodePort:
> 
> - **Admin dashboards** (Prometheus, Grafana)
> - **Temporary external access** (testing, demos)
> - **Bare-metal clusters without MetalLB**

### 🆚 Service Types in k3s

| Type | External Access | Port Range | Use Case |
| --- | --- | --- | --- |
| **ClusterIP** | ❌ No | N/A | Internal microservices |
| **NodePort** | ✅ Yes | `30000-32767` | Dev/testing, admin tools |
| **LoadBalancer** | ✅ Yes | Any | Production (requires MetalLB) |

> 💡 To get LoadBalancer in k3s:
> 
> 
> Install [MetalLB](https://metallb.io/) → then `type: LoadBalancer` gives you a **real external IP**.

### ❓ Common Questions

**Q: What if I omit `nodePort`?**

A: k3s assigns a **random port** in `30000-32767` → check with `kubectl get svc`.

**Q: Can I use ports outside 30000-32767?**

A: ❌ **No!** Kubernetes enforces this range (configurable at cluster level).

**Q: Does NodePort work if the Pod is on a different node?**

A: ✅ **Yes!** kube-proxy handles **cross-node forwarding**.

**Q: Is NodePort secure?**

A: ⚠️ It exposes ports on **all nodes**.

✅ **Always pair with**:

- Firewall rules
- Network Policies (if using CNI like Cilium)
- Authentication in the app
