# 9.4: PersistentVolume (PV) with NFS

### 🔍 YAML Breakdown

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pvone-nfs
spec:
  capacity:
    storage: 5Gi                 # ← Total storage size
  volumeMode: Filesystem         # ← Standard filesystem (not block)
  accessModes:
    - ReadWriteOnce              # ← RWO: one node at a time
  persistentVolumeReclaimPolicy: Recycle  # ← What to do when PVC is deleted
  storageClassName: slow         # ← Links to StorageClass (optional)
  nfs:
    path: /foldername            # ← Exported directory on NFS server
    server: ip-address-nfs-server # ← NFS server IP/DNS

```

> 🔑 Key Insight:
> 
> 
> This PV represents **5Gi of shared storage** on an **NFS server**, accessible to **any Pod in the cluster** (as long as it’s on a node that can reach the NFS server).
> 

> 💡 Why NFS?
> 
> - **Shared storage**: Multiple Pods can access the same data (with proper `accessModes`)
> - **Multi-node safe**: Data isn’t tied to a specific k3s node
> - **Cheap & simple**: Runs on any Linux server

---

### 📌 Critical Concepts Explained

### 1. **`accessModes`**

| Mode | Meaning | NFS Support |
| --- | --- | --- |
| **`ReadWriteOnce` (RWO)** | Read-write by **one node** | ✅ Yes |
| **`ReadOnlyMany` (ROX)** | Read-only by **many nodes** | ✅ Yes |
| **`ReadWriteMany` (RWX)** | Read-write by **many nodes** | ✅ **Yes!** (NFS’s superpower) |

> ⚠️ Your PV uses ReadWriteOnce → but NFS supports ReadWriteMany!
> 
> 
> ✅ **For shared storage (e.g., web servers)**, use `ReadWriteMany`.
> 

### 2. **`persistentVolumeReclaimPolicy`**

| Policy | Behavior |
| --- | --- |
| **`Retain`** | Keep PV + data (manual cleanup) |
| **`Delete`** | Delete PV + data (cloud disks) |
| **`Recycle`** | **Deprecated!** Runs `rm -rf` (unsafe) |

> 🚨 Critical Warning:
> 
> 
> **`Recycle` is deprecated since Kubernetes 1.11!**
> 
> ✅ **Use `Retain`** (for NFS) or `Delete` (for cloud).
> 

### 3. **`storageClassName`**

- Links PV to a **StorageClass** (for dynamic provisioning)
- If **not set**, PV is **statically provisioned** (your case)

### 🧪 k3s Lab: Test NFS PersistentVolume

> 💡 Don’t have an NFS server?
> 
> 
> We’ll use a **k3s node as NFS server** (for lab purposes).
> 

### 🔧 Step 1: Set Up NFS Server (On a k3s Node)

> 📝 Run on one k3s node (e.g., k3s-master):
> 

```bash
# Install NFS server
sudo apt update && sudo apt install -y nfs-kernel-server

# Create shared directory
sudo mkdir -p /foldername
sudo chmod 777 /foldername

# Export directory
echo "/foldername *(rw,sync,no_subtree_check)" | sudo tee -a /etc/exports

# Restart NFS
sudo exportfs -a
sudo systemctl restart nfs-kernel-server

```

> 🔍 Get NFS server IP:
> 
> 
> ```bash
> ip addr show  # Note the node's IP (e.g., 192.168.1.10)
> 
> ```
> 

### 🔧 Step 2: Create PersistentVolume

> 💡 Update YAML with real NFS server IP:
> 

```yaml
# persistent-volume-nfs.yaml (updated)
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pvone-nfs
spec:
  capacity:
    storage: 5Gi
  accessModes:
    - ReadWriteMany        # ← Changed to RWX for shared access
  persistentVolumeReclaimPolicy: Retain  # ← Fixed deprecated policy
  storageClassName: slow   # ← Storage class name
  nfs:
    path: /nfs
    server: 192.168.1.10   # ← Your NFS server IP

```

```bash
# Apply PV
kubectl apply -f persistent-volume-nfs.yaml

# Verify
kubectl get pv
# NAME        CAPACITY  ACCESS MODES  RECLAIM POLICY  STATUS      CLAIM
# pvone-nfs   5Gi       RWX           Retain          Available   <none>

```

### 💡 Real-World NFS PV Best Practices

| Setting | Recommendation |
| --- | --- |
| **`accessModes`** | Use `ReadWriteMany` for shared apps (web servers, CMS) |
| **`reclaimPolicy`** | **`Retain`** (NFS) or **`Delete`** (cloud) |
| **Permissions** | Set `chmod 777` or match Pod’s `runAsUser` |
| **Security** | Restrict NFS exports to k3s node IPs: |
| `/foldername 192.168.1.0/24(rw,sync)` |  |

> ✅ Why NFS over hostPath?
> 
> - Works in **multi-node clusters**
> - **Shared access** (`ReadWriteMany`)
> - **Centralized management**

### 🆚 Static vs Dynamic Provisioning

| Approach | How It Works | Your Case |
| --- | --- | --- |
| **Static PV** | Admin creates PV → User creates PVC to claim it | ✅ Your YAML |
| **Dynamic PV** | User creates PVC → StorageClass auto-creates PV | `storage-class-nfs` (next topic) |

> 💡 Static provisioning = manual, good for labs
> 
> 
> **Dynamic provisioning** = automated, good for production
>

### ❓ Common Questions

**Q: What if NFS server is down?**

A: Pods **hang** on mount → use **timeout settings** or **monitor NFS**.

**Q: Can I use NFS with StatefulSets?**

A: ✅ **Yes!** Perfect for shared storage (e.g., WordPress + NFS).

**Q: Why is `Recycle` deprecated?**

A: It ran `rm -rf` as root → **security risk**. Use `Retain` + manual cleanup.

**Q: Does k3s support NFS?**

A: ✅ **Yes!** Just install `nfs-common` on all k3s nodes:

```bash
sudo apt install -y nfs-common

```
