### 🎯 What It Is

A **ConfigMap** is a Kubernetes resource that stores **non-sensitive configuration data** (like app settings, feature flags, log levels) as key-value pairs — **separate from your container image**.

> ✅ Why? So you can change config without rebuilding your image.
> 

### 💡 Real-World Analogy

> Think of a ConfigMap like a .env file or app.conf — but managed by Kubernetes and injected into your Pods safely.
> 

---

### 🧪 Example: Inject App Settings as Environment Variables

**Step 1: Create a ConfigMap**

```yaml
# app-config.yaml
apiVersion: v1
kind: ConfigMap
meta
  name: webapp-config
  namespace: dev
data:
  LOG_LEVEL: "info"
  FEATURE_NEW_UI: "true"
  API_TIMEOUT: "5000"

```

Apply it:

```bash
kubectl apply -f app-config.yaml

```

**Step 2: Use It in a Pod**

```yaml
# webapp-pod.yaml
apiVersion: v1
kind: Pod
meta
  name: webapp
  namespace: dev
spec:
  containers:
  - name: app
    image: nginx
    envFrom:
    - configMapRef:
        name: webapp-config  # ← Inject all keys as env vars

```

Apply and test:

```bash
kubectl apply -f webapp-pod.yaml
kubectl exec webapp -n dev -- printenv | grep LOG_LEVEL
# Output: LOG_LEVEL=info

```

✅ **Result**: Your app reads config from environment — no hardcoded values!

### ✅ Summary YAML

```yaml
# Create ConfigMap
apiVersion: v1
kind: ConfigMap
meta
  name: my-config
data:
  KEY1: "value1"
  KEY2: "value2"

# Use in Pod
envFrom:
- configMapRef:
    name: my-config

```

### ❓ Common Questions

**Q: Can I update a ConfigMap and have Pods see the change?**

➡️ **If using `envFrom`**: ❌ No — Pods must be **recreated**.

➡️ **If mounted as volume**: ✅ Yes — files auto-update in ~1 minute.

**Q: What’s the max size of a ConfigMap?**

➡️ **1 MiB** (same as etcd object limit).

**Q: Can I use ConfigMap across namespaces?**

➡️ ❌ No — ConfigMaps are **namespaced**. Create one per namespace.

### 🛠️ Best Practices

1. ✅ **Use for non-sensitive data only** (never passwords!)
2. ✅ Prefer `envFrom` for many variables, `valueFrom` for one or two:
    
    ```yaml
    env:
    - name: TIMEOUT
      valueFrom:
        configMapKeyRef:
          name: my-config
          key: API_TIMEOUT
    
    ```
    
3. ✅ For config **files** (like `nginx.conf`), **mount as volume** (next topic!)
4. ✅ Store ConfigMap YAML in Git — it’s safe!
