# **12.1 : What Is a NetworkPolicy? (The Kubernetes Firewall)**

### 🎯 What It Is

A **NetworkPolicy** is a Kubernetes resource that **controls traffic flow** between Pods — like a **firewall for your cluster**.

> ✅ By default, all Pods can talk to each other (open network).
> 
> 
> 🔒 **NetworkPolicy adds restrictions** — “only allow X to talk to Y”.
> 

### 💡 Real-World Analogy

> Like a building security system:
> 
> - Without policy: Anyone can walk into any office
> - With policy: Only HR can enter payroll room; devs can only access dev servers

---

### 🧪 Example: Isolate a “Frontend” Pod

**Step 1: Deploy two apps (no policy yet)**

```yaml
# frontend.yaml
apiVersion: apps/v1
kind: Deployment
meta
  name: frontend
  labels:
    app: frontend
spec:
  selector:
    matchLabels:
      app: frontend
  template:
    meta
      labels:
        app: frontend
    spec:
      containers:
      - name: nginx
        image: nginx
---
apiVersion: v1
kind: Service
meta
  name: frontend
spec:
  selector:
    app: frontend
  ports:
  - port: 80

```

```yaml
# backend.yaml
apiVersion: apps/v1
kind: Deployment
meta
  name: backend
  labels:
    app: backend
spec:
  selector:
    matchLabels:
      app: backend
  template:
    meta
      labels:
        app: backend
    spec:
      containers:
      - name: httpd
        image: httpd

```

Apply:

```bash
kubectl apply -f frontend.yaml -f backend.yaml

```

✅ **Right now**: `frontend` can `curl <http://backend`> → **allowed**

---

### 🧪 Step 2: Apply a NetworkPolicy to Restrict Access

```yaml
# deny-all-backend.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
meta
  name: deny-all-to-backend
  namespace: default
spec:
  podSelector:
    matchLabels:
      app: backend   # ← Applies to Pods with this label
  policyTypes:
  - Ingress          # ← Control incoming traffic
  ingress: []        # ← Empty = deny ALL

```

Apply:

```bash
kubectl apply -f deny-all-backend.yaml

```

Now test:

```bash
# From frontend Pod
kubectl exec deploy/frontend -- curl -m 3 <http://backend>
# ❌ Connection timed out!

```

✅ **Result**: Backend is now **isolated** — no one can reach it!

### ✅ Summary YAML

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
meta
  name: my-policy
spec:
  podSelector:
    matchLabels:
      app: target-pod
  policyTypes:
  - Ingress    # incoming
  - Egress     # outgoing (optional)
  ingress: []  # empty = deny all

```

> 🔑 Key Fields:
> 
> - `podSelector`: Which Pods does this policy apply to?
> - `policyTypes`: `Ingress`, `Egress`, or both
> - `ingress/egress`: Rules to **allow** traffic (empty = deny all)

### ❓ Common Questions

**Q: Does NetworkPolicy work by default in k3s?**

➡️ ❌ **No!** k3s uses **Flannel** by default, which **does not support NetworkPolicy**.

✅ **Fix**: Install a **CNI that supports NetworkPolicy**, like:

- **Cilium** (recommended)
- **Calico**
- **Weave Net**

> 💡 For this chapter, we’ll assume you’ve installed Cilium:
> 
> 
> ```bash
> k3s-uninstall.sh  # if needed
> curl -L --remote-name <https://github.com/cilium/cilium-cli/releases/latest/download/cilium-linux-amd64.tar.gz>
> tar xzvfC cilium-linux-amd64.tar.gz /usr/local/bin
> cilium install
> 
> ```
> 

**Q: What if I don’t apply any NetworkPolicy?**

➡️ All Pods can communicate freely (open network).

**Q: Are NetworkPolicies additive or restrictive?**

➡️ **Restrictive**: You start with **full access**, then **add policies to restrict**.

### 🛠️ Best Practices

1. ✅ **Start with “default deny”**:
    
    ```yaml
    # Deny all ingress in namespace
    spec:
      podSelector: {}
      policyTypes: ["Ingress"]
      ingress: []
    
    ```
    
2. ✅ **Apply policies per namespace** (e.g., `dev`, `prod`)
3. ✅ **Label Pods clearly** (`app: frontend`, `tier: backend`)
4. ✅ **Test with `kubectl exec` + `curl`** before deploying to prod
5. ✅ **Use `policyTypes` explicitly** — don’t rely on implicit behavior
