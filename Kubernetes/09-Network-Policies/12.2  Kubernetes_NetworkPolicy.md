# 12.2 : Allow Traffic from Specific Pods (Ingress Rules)**

### 🎯 What It Is

A **NetworkPolicy ingress rule** lets you **allow traffic only from specific Pods** (e.g., “only frontend can talk to backend”).

> ✅ This is the most common use case for NetworkPolicy in microservices apps.
> 

### 💡 Real-World Analogy

> Like a VIP list at a club:
> 
> - Only guests with a **green wristband** (`app: frontend`) can enter the **VIP room** (`app: backend`)

---

### 🧪 Example: Allow Only `frontend` to Access `backend`

**Assume you already have:**

- A `frontend` Deployment (label: `app: frontend`)
- A `backend` Deployment (label: `app: backend`)
- **Cilium or Calico** installed (NetworkPolicy enabled)

**Step 1: Apply a NetworkPolicy to Allow Only `frontend`**

```yaml
# allow-frontend-to-backend.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
meta
  name: allow-frontend-to-backend
  namespace: default
spec:
  podSelector:
    matchLabels:
      app: backend          # ← Policy applies to backend Pods
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend     # ← Only Pods with this label can connect
    ports:
    - protocol: TCP
      port: 80

```

Apply it:

```bash
kubectl apply -f allow-frontend-to-backend.yaml

```

**Step 2: Test Access**

✅ **From frontend → backend (should work):**

```bash
kubectl exec deploy/frontend -- curl -m 3 <http://backend>
# ✅ Returns HTTP response

```

❌ **From any other Pod → backend (should fail):**

```bash
# Create a test Pod (not labeled as frontend)
kubectl run tester --image=busybox --rm -it -- sh
/ # wget -qO- <http://backend>
# ❌ Hangs or times out

```

✅ **Result**: Only `frontend` can reach `backend`!

### ✅ Summary YAML

```yaml
spec:
  podSelector:
    matchLabels:
      app: target
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: allowed-source
    ports:
    - port: 80

```

> 🔑 Key Fields:
> 
> - `podSelector` in **policy spec**: Which Pods are **protected**?
> - `podSelector` in **ingress.from**: Which Pods are **allowed**?

---

### ❓ Common Questions

**Q: What if the `frontend` is in a different namespace?**

➡️ Use `namespaceSelector`:

```yaml
ingress:
- from:
  - namespaceSelector:
      matchLabels:
        env: prod
    podSelector:
      matchLabels:
        app: frontend

```

**Q: Can I allow traffic from a Service?**

❌ No! NetworkPolicy works at **Pod level**, not Service level.

✅ Use the **Pod labels** that the Service selects.

**Q: Does this work with headless Services?**

✅ Yes! NetworkPolicy applies to **Pod IPs**, not Services.

**Q: What protocol does it support?**

➡️ **TCP, UDP, SCTP** (but most use TCP for HTTP).

---

### 🛠️ Best Practices

1. ✅ **Always label Pods clearly**:
    
    ```yaml
    labels:
      app: frontend
      tier: web
    
    ```
    
2. ✅ **Use `ports` to restrict to specific ports** (don’t allow all)
3. ✅ **Start with deny-all**, then add allow rules (least privilege)
4. ✅ **Test with a generic Pod** (like `busybox`) to verify isolation
5. ✅ **Combine with namespace labels** for multi-tenant clusters:
    
    ```yaml
    namespaceSelector:
      matchLabels:
        team: dev
    
    ```
