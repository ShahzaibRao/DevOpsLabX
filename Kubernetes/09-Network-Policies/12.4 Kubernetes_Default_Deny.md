# 12.4 : Default Deny Policies (Namespace Isolation)**

### 🎯 What It Is

A **“default deny” NetworkPolicy** blocks **all traffic** (ingress and/or egress) in a namespace by default — then you **explicitly allow only what’s needed**.

> ✅ This is the gold standard for security in multi-tenant or production clusters.
> 

### 💡 Real-World Analogy

> Like a secure data center:
> 
> - All doors are **locked by default**
> - Access is granted **only after approval** (whitelisted traffic)

---

### 🧪 Example: Isolate the `prod` Namespace

**Step 1: Create a “default deny all” policy for `prod`**

```yaml
# default-deny-prod.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
meta
  name: default-deny-all
  namespace: prod
spec:
  podSelector: {}           # ← Applies to ALL Pods in namespace
  policyTypes:
  - Ingress
  - Egress
  ingress: []               # ← Deny all incoming
  egress: []                # ← Deny all outgoing

```

Apply it:

```bash
kubectl create namespace prod
kubectl apply -f default-deny-prod.yaml

```

✅ **Result**:

- No Pod in `prod` can talk to **anything inside or outside the cluster**
- Even `kubectl exec` + `curl localhost` works, but **no network calls**

---

### 🧪 Step 2: Allow Essential Traffic (e.g., DNS + Internal Services)

Now, **add allow rules** for what’s needed:

```yaml
# allow-dns-and-backend.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
meta
  name: allow-dns-and-backend
  namespace: prod
spec:
  podSelector:
    matchLabels:
      app: frontend
  policyTypes:
  - Egress
  egress:
  # Allow DNS (required for service name resolution)
  - ports:
    - port: 53
      protocol: UDP
    - port: 53
      protocol: TCP

  # Allow frontend → backend
  - to:
    - podSelector:
        matchLabels:
          app: backend
    ports:
    - port: 80

```

Apply:

```bash
kubectl apply -f allow-dns-and-backend.yaml

```

Now:
✅ `frontend` can resolve `backend` and connect to it

❌ `frontend` **cannot** reach the internet or other namespaces

### ✅ Summary YAML

```yaml
# Default deny ALL
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
meta
  name: default-deny
  namespace: my-ns
spec:
  podSelector: {}
  policyTypes: ["Ingress", "Egress"]
  ingress: []
  egress: []

```

> 🔑 Key Trick:
> 
> - `podSelector: {}` = **all Pods** in the namespace
> - Empty `ingress/egress` = **deny all**

### ❓ Common Questions

**Q: Do I need separate policies for ingress and egress?**

✅ You can combine them (as above), or split into two policies — same effect.

**Q: Does this block traffic within the same Pod (localhost)?**

❌ No! `localhost` traffic is **not affected** — NetworkPolicy only applies to **Pod-to-Pod** or **Pod-to-external**.

**Q: What about kube-system Pods (CoreDNS, etc.)?**

➡️ They run in **other namespaces** — so your `prod` policy doesn’t affect them.

✅ But your `prod` Pods **can’t reach CoreDNS** unless you allow DNS!

**Q: Can I apply default deny cluster-wide?**

❌ No — NetworkPolicy is **namespace-scoped**.

✅ Apply it to **every namespace** you want to secure.

---

### 🛠️ Best Practices

1. ✅ **Apply default deny to every production namespace**
2. ✅ **Always allow DNS** (port 53 UDP/TCP) if using service names
3. ✅ **Label namespaces** (`env: prod`, `team: finance`) for easier policy management
4. ✅ **Test with a debug Pod**:
    
    ```bash
    kubectl run debug -n prod --image=busybox --rm -it -- sh
    / # nslookup backend  # Should work if DNS allowed
    / # wget -qO- <http://backend>  # Should work if policy allows
    
    ```
    
5. ✅ **Use CI/CD to enforce** default-deny in new namespaces
